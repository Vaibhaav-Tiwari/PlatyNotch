# Plan 2: Local personal memory and MCP

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement `memory.Service`: store captured on-screen text locally, search it (keyword + vector), find open loops with a user-chosen AI provider, and expose it to Claude Desktop, Claude Code and Cursor through `notch mcp`.

**Architecture:** One SQLite file (`memory.db`, WAL) owned by `notch serve`. Text flows thread → hourly version → chunks; chunks get FTS5 rows immediately and vectors/loop extraction from a background worker with retries. `notch mcp` is a separate stdio process that reads the DB read-only and sends writes through the core socket. Providers are pluggable by name so Pro can add a hosted one.

**Tech Stack:** Go 1.27, `modernc.org/sqlite` (pure Go, FTS5), `github.com/modelcontextprotocol/go-sdk` v1.1.0. Vectors are float32 BLOBs searched by brute-force cosine (enough for one person; swap for sqlite-vec later behind the same function).

**Spec:** `docs/specs/2026-10-23-platynotch-design.md`
**Depends on:** Plan 1 (`memory.Service` interface, `protocol`, `config`, `cli.WithMemory`, server routing of `capture.text` / `memory.search` / `loop.set_status`).

## Global Constraints

- Memory is off unless `config.Memory.Enabled`; with provider `none` everything except vectors and loop extraction still works (FTS search).
- DB file mode 0600 inside the data dir; at-rest protection relies on FileVault (documented in README; SQLCipher is out of scope for pure-Go SQLite).
- Never store text from `config.Memory.ExcludeApps`; drop captures shorter than 40 chars; truncate at 200 000 chars.
- Redact before storage: card numbers passing Luhn (13–19 digits), `sk-[A-Za-z0-9_-]{20,}`, `AKIA[0-9A-Z]{16}`, JWTs (`eyJ…\.…\.…`), `-----BEGIN … PRIVATE KEY-----` blocks → `[redacted]`.
- Retention: delete versions/chunks older than `RetentionDays` (default 90) daily; loops are kept.
- Provider calls time out after 30 s; failures go to the retry queue with backoff 1 min, 5 min, 30 min, 2 h, then `failed`.
- No network calls happen unless the user configured a provider.

## Review Focus

- Provider down or key invalid → captures still stored, FTS search still answers, `Status().LastError` set (Task 5).
- Same text captured every 20 s for hours → one version per thread per hour, no duplicate chunks (Task 2).
- Secrets on screen (API key in a terminal) → stored as `[redacted]` (Task 2).
- Embedding model changed in settings → old vectors ignored by search and re-embedded, never mixed (Task 4).
- MCP client asks a question while the core is not running → read-only answers still work; `resolve_loop` returns a clear error (Task 8).

### Task 4: Hybrid search

**Files:**
- Create: `core/memory/search/search.go`, `search_test.go`

**Interfaces:**
- Consumes: `store`, `provider.Embedder`.
- Produces: `func Search(ctx context.Context, s *store.Store, e provider.Embedder, q protocol.MemorySearch) ([]protocol.MemoryHit, error)`; `func Cosine(a, b []float32) float32`.
- Algorithm: FTS5 bm25 top 50 (query tokens quoted, so user punctuation cannot break MATCH) and, when `e != nil`, cosine top 50 over vectors whose `model == e.Model()` among the 50 000 most recent; fuse with reciprocal rank `score = Σ 1/(60 + rank)`; apply Since/Until/App filters before ranking; group by thread keeping the best chunk; Limit default 10, max 50; Snippet = chunk text trimmed to 300 runes around the first query term.
